# 추천 다양성과 RAG 검증 결과

목표는 **날씨에 맞는 보유 의상으로 기본 코디의 반복을 줄이는 것**이다. 작은 표본에서 다양성 개선 신호와 실제 RAG 연결을 확인했다. 전체 추천 품질 향상이나 항상 빠른 첫 요청을 보장하지 않는다.

설정·구현 정책은 [LLM·RAG 문서](recommendation-rag.md), 기본 복구 규칙은 [기본 알고리즘 문서](recommendation-design.md)를 참고한다. LLM 추천은 RAG 검색·캐시 조회를 항상 거치며 별도 RAG 비활성화 설정은 없다.

## RAG 상시 경로 확인

실행 중인 앱 두 개에서 과거 RAG 활성화 환경변수가 없는 것을 확인했다. 이 상태의 실제 추천 API에서 Redis 자료 2개를 읽고 `messages=3`, `ragContext=true`로 Groq에 전송한 뒤 응답 채택·HTTP 200을 확인했다. 전체 요청은 약 4,259ms, 실제 Groq 호출은 1회였다. 검증 데이터는 삭제했고 로그아웃 HTTP 204·잔여 테스트 행 0개를 확인했다. 자료가 없거나 검색 장애·대기 초과가 있는 경우의 문맥 없는 복구는 유지한다.

## 최근 이력 1개와 5개 비교

동일 옷장·날씨·초기 이력에서 `openai/gpt-oss-120b`를 각각 5회 연속 호출했다. 19℃·맑음·민감도 3의 가을 사례로, 갈색 보통 두께 긴팔 4개와 검정 긴바지 2개의 기본 조합 8개를 준비했다. 실제 검색한 동일 자료 2개를 첨부하고 각 분기의 채택 결과로 다음 이력을 갱신했다.

| 5회 결과 | 최근 1개 | 최근 5개 |
| --- | ---: | ---: |
| 고유 기본 조합 | 3개 | 5개 |
| 날씨 기준을 통과한 고유 기본 조합 | 3개 | 4개 |
| 날씨 기준 통과 | 5/5 | 4/5 |
| HTTP 성공·구조 검증 통과 | 5/5 | 5/5 |

신발·아우터 교체는 새 기본 조합으로 세지 않는다. 최근 5개 쪽의 초박형 린넨 쇼츠 선택 1회가 사전 기준을 통과하지 못했다. 19℃ 쇼츠 제외는 이 시험의 보수적인 기준이며 모든 사용자에게 부적합하다는 뜻은 아니다.

한 옷장에 각 5회인 탐색 결과다. 이력 길이가 날씨 실패를 유발했다고 단정하지 않는다. 이 비교는 운영 DTO·클라이언트·검증기를 사용하되 HTTP API·업무 DB·Redis는 거치지 않는 독립 메모리 이력으로 수행했다.

## 사전 검색·Redis 공유 검증

LLM·RAG를 활성화한 실제 로컬 앱 두 개와 DB·Redis·Ollama·pgvector·Groq를 사용했다. 공유 캐시가 비어 있는 상태에서 검증 계정·옷장·19℃ 날씨를 준비하고, 추천 요청보다 먼저 의상 수정 API를 호출했다.

| 단계 | 관찰 |
| --- | --- |
| 의상 수정 | HTTP 200, 약 1,294ms. 검색 완료를 기다리지 않음 |
| app-2 사전 검색 | 수정 응답 후 약 9.5초에 참고 자료 2개 준비·Redis 저장. Groq 호출 없음 |
| app-1 첫 추천 | Redis 적중 2개, messages=3·ragContext=true, Groq 응답 채택 |
| 추천 응답 | HTTP 200, 소유 의상 2개, 전체 요청 약 4,932ms |

실제 Groq 호출은 1회였다. 검증 계정·의상·속성 정의·날씨·이력은 삭제했고 잔여 테스트 행 0개와 로그아웃 HTTP 204를 확인했다.

자료 공유·사전 준비를 확인한 단일 요청이며 일반적인 속도 개선율은 아니다. API 시간은 인증·DB·Groq 등을 포함한다. 자료 준비 전·캐시 만료·작업 포화 시 첫 검색 대기는 남을 수 있다. Redis 장애에는 로컬 검색으로 복구하고 검색 대기 초과에는 LLM 단독으로 복구한다.

## 자동 검증

```bash
# Docker 필요. 실제 Groq·Ollama API 호출 없음
./gradlew test --tests 'com.otboo.team03.recommendation.*' --tests 'com.otboo.team03.clothes.*' --tests 'com.otboo.team03.global.client.groq.*' bootJar
```

RAG 상시 경로 변경 후 추천·의상·Groq 회귀 테스트 **731개 통과, 실패·오류·생략 0개**, `bootJar` 성공을 확인했다. 별도 활성화 설정 없이 실제 검색 provider를 구성하는 것도 검증했다. 핵심 범위는 다음과 같다.

- 소유권·코디 조합·전체 속성·예보 날짜 전달과 기본 추천 복구
- 실제 Redis의 최근 5개 이력·TTL·이전 형식 호환
- 임베딩 응답 검증·pgvector 순위·모델/자료 버전 격리·원자적 인덱싱
- 문맥 필터·길이 제한, 캐시 변경 감지·TTL·공유·손상/장애 복구
- 의상 커밋 후 비동기 준비와 롤백 시 미실행
