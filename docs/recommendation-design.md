# 기본 의상 추천 알고리즘

LLM 비활성화·예상된 호출 장애·응답 검증 실패 시 사용하는 기본 정책이다. 두께·소매·보정 온도로 의상을 선택하며, 계절 색감과 자유 속성 해석은 [LLM 추천](recommendation-rag.md)에서 담당한다.

## 입력과 속성 해석

서비스는 날씨·프로필·소유 의상과 전체 속성을 조회한다. 속성을 의상 ID별로 묶어 두께·소매를 각각 해석하며 결과를 따로 저장하지 않는다. 의상·속성·민감도 변경은 다음 요청에서 다시 반영한다. 보유 의상이 없으면 속성 조회를 생략한다.

| 속성명 | 값 | 해석 |
| --- | --- | --- |
| 두께, 두께감 | 얇음 | `LIGHT` |
| 두께, 두께감 | 보통 | `MEDIUM` |
| 두께, 두께감 | 두꺼움, 도톰함 | `HEAVY` |
| 소매, 소매 길이 | 반팔 | `SHORT` |
| 소매, 소매 길이 | 긴팔 | `LONG` |
| 그 외·누락·null | 모든 값 | `UNKNOWN` |

- 이름과 값의 앞뒤 공백만 제거하고 사전과 정확히 일치하는 표현을 해석한다. 중간 공백·부분 문자열·제목으로 추측하지 않는다.
- 같은 의상의 동일 수준은 중복 가산하지 않는다. `UNKNOWN`과 유효 값이 함께 있으면 유효 값을 사용한다.
- 서로 다른 유효 값이 충돌하면 `UNKNOWN`이다. 개수가 많은 값을 우선하지 않는다.
- 두께와 소매는 독립적으로 종합한다. 한쪽 충돌이 다른 정보를 없애지 않는다.
- `UNKNOWN`은 정보 부족이며 보통 두께를 뜻하지 않는다. 민소매·7부·9부 등 미지원 표현도 `UNKNOWN`이다.

예: `두께감=도톰함`은 `HEAVY`, `가격대=두꺼움`과 `두께=두꺼움 아님`은 `UNKNOWN`이다.

## 온도와 선택 순위

### 보정 온도

```text
보정 온도 = 실제 기온 + (온도 민감도 - 3) × 2.0
```

민감도 기본값은 3이다. 현재 식에서는 값이 작을수록 추위를 타는 방향, 클수록 더위를 타는 방향으로 동작한다. 실제 17℃라면 민감도 1·3·5의 보정 온도는 각각 13·17·21℃다.

보정은 한 번만 수행해 두께·소매·아우터·스카프에 공통으로 사용한다. 중간 온도 구간에서만 민감도를 차선 두께와 선호 소매 결정에도 사용하며 온도를 다시 보정하지 않는다.

### 두께 순위

| 보정 온도 | 조건 | 우선순위 |
| --- | --- | --- |
| 15℃ 미만 | 모든 민감도 | HEAVY → MEDIUM → UNKNOWN → LIGHT |
| 15℃ 이상·25℃ 미만 | 민감도 1·2, 또는 민감도 3이면서 20℃ 미만 | MEDIUM → HEAVY → UNKNOWN → LIGHT |
| 15℃ 이상·25℃ 미만 | 민감도 4·5, 또는 민감도 3이면서 20℃ 이상 | MEDIUM → LIGHT → UNKNOWN → HEAVY |
| 25℃ 이상 | 모든 민감도 | LIGHT → MEDIUM → UNKNOWN → HEAVY |

순위별 점수는 3·2·1·0이다. 앞선 후보가 없어도 남은 후보 점수를 다시 계산하지 않는다. 부적합한 두께도 최후 후보로 유지하며, 그 후보만 있어도 기본 조합을 만들 수 있으면 반환한다.

15℃는 중간 구간, 20℃는 중립 민감도의 차선 전환점, 25℃는 더운 구간에 포함된다. 온도 구간은 프로젝트 내부 정책이며 실제 체감 온도를 보장하지 않는다.

### 두께 동점에서 소매 비교

소매는 `TOP`·`DRESS`에만 적용한다. 다른 종류의 소매 점수는 0이다.

| 보정 온도 | 조건 | 선호 소매 |
| --- | --- | --- |
| 15℃ 미만 | 모든 민감도 | 긴팔 |
| 15℃ 이상·25℃ 미만 | 민감도 1·2, 또는 민감도 3이면서 20℃ 미만 | 긴팔 |
| 15℃ 이상·25℃ 미만 | 민감도 4·5, 또는 민감도 3이면서 20℃ 이상 | 반팔 |
| 25℃ 이상 | 모든 민감도 | 반팔 |

선호 소매 2점 → `UNKNOWN` 1점 → 반대 소매 0점이다. 두께와 소매 점수는 합산하지 않는다.

```text
두께 점수 높은 순
  → 두께 동점이면 소매 점수 높은 순 (TOP·DRESS)
  → 적합도 동점이면 직전에 없는 기본 의상·아우터 우선
  → 나머지 동점은 입력 순서 유지
```

더운 날 `LIGHT·긴팔`과 `HEAVY·반팔`이 있으면 두께를 우선해 전자를 고른다. 두 정보가 모두 `UNKNOWN`이면 입력 순서와 직전 이력으로 선택한다. DB 조회 순서가 달라지면 최종 동점 선택도 달라질 수 있다.

## 코디 구성과 반복 완화

### 기본 조합과 추가 아이템

| 종류 | 포함 조건 | 최대 개수 |
| --- | --- | ---: |
| 상의 + 하의 | 둘 다 있으면 원피스보다 우선 | 각각 1 |
| 원피스 | 상의·하의 조합을 만들 수 없을 때 대체 | 1 |
| 아우터 | 기본 조합이 있고 보정 온도 15℃ 미만 | 1 |
| 신발·가방·모자·액세서리 | 기본 조합이 있고 해당 의상을 보유 | 각각 1 |
| 양말 | 신발이 선택됨 | 1 |
| 스카프 | 기본 조합이 있고 보정 온도 15℃ 미만. 아우터 유무와 무관 | 1 |
| 속옷·기타 | 제외 | 0 |

기본 조합을 만들 수 없으면 추가 아이템도 선택하지 않고 빈 목록을 반환한다. 정확히 15℃이면 아우터·스카프를 추가하지 않는다. 아우터는 두께 순위로 선택하고 추가 아이템은 두께·소매 평가 없이 원래 입력 순서에서 고른다.

응답 순서는 고정하고 없는 종류는 건너뛴다.

```text
(상의 → 하의) 또는 원피스
  → 아우터 → 신발 → 양말 → 가방 → 모자 → 액세서리 → 스카프
```

### 직전 결과를 이용한 선택

- 기본 알고리즘은 최근 이력 중 **직전 결과 1개**만 사용한다.
- 같은 종류에서 최상위 적합도의 다른 후보가 있으면 직전에 없던 의상을 우선한다. 다양화를 위해 두께·소매 적합도를 낮추지 않는다.
- 상의·하의 조합이 가능하면 다양화를 위해 원피스로 전환하지 않는다.
- 추가 아이템은 같은 종류의 직전에 없던 첫 후보를 선택하고, 없으면 기존 첫 후보를 유지한다. 포함 조건을 만족하는 아이템을 임의로 생략하지 않는다.
- 대안이 없으면 동일 결과를 허용한다. 전체 조합의 순환이나 동시 요청 간 서로 다른 결과를 보장하지 않는다.

## API와 이력

```http
GET /api/recommendations?weatherId={UUID}
```

사용자는 인증 정보로 식별한다. 화면 진입·새로고침·다른 옷 추천 버튼을 구분하지 않고 매 요청에 최신 입력과 이력을 사용한다. 응답은 `Cache-Control: no-store`이며 완성된 추천 결과를 캐시하지 않는다. RAG의 참고 문맥 캐시와는 별개다.

| 항목 | 정책 |
| --- | --- |
| 입력 조회 | 짧은 조회 트랜잭션 종료 후 외부 LLM 호출 |
| 이력 저장 | Redis, 사용자 ID + weatherId별 최근 5개 결과 |
| 보관 기간 | 마지막 저장부터 30분. 조회로 연장하지 않음 |
| 최종 결과 | LLM 채택·기본 복구 결과 중 실제 응답한 의상 ID 기록 |
| 빈 결과 | 해당 사용자·날씨의 직전·최근 이력 모두 삭제 |
| 읽기 호환 | 이전 배포의 직전 문자열 이력을 합쳐 최신순으로 조회 |
| 손상된 이력 | 최근 이력의 잘못된 UUID 항목은 건너뜀 |

Redis 연결 장애·시간 초과 시 조회는 빈 이력으로 처리하고 저장·삭제 실패도 추천 응답을 막지 않는다. 이 경우 반복 결과나 복구 후 이전 이력 사용이 발생할 수 있다. 예상하지 못한 Redis·코드 오류는 전파한다. 기록은 서버 응답 기준이며 사용자가 화면에서 확인했는지 추적하지 않는다.

LLM에는 현재 소유 중인 완전한 기본 조합을 중복 제거해 최대 5개 전달한다. 상세 정책은 [LLM·RAG 문서](recommendation-rag.md)의 서버 검증과 이력을 참고한다.

## 검증

```bash
# 추천 관련 단위·서비스·API·DB/Redis 통합 테스트 (Docker 필요)
./gradlew test --tests 'com.otboo.team03.recommendation.*'
```

| 범위 | 핵심 검증 |
| --- | --- |
| 속성 해석 | 정확한 이름·값, 누락·미지원·충돌·중복, 두께·소매 독립성 |
| 적합도·조합 | 15·20·25℃ 경계, 민감도·차선 순위, 두께 우선, 후보 부족·추가 아이템·응답 순서 |
| 서비스·API | 소유권, 속성 변경 반영, 민감도 기본값, 이미지·속성 응답 보존, no-store |
| Redis | 사용자·날씨 분리, 최신 5개·TTL·삭제·이전 형식 호환, 장애 복구 |

통합 테스트는 전용 PostgreSQL·Redis 컨테이너를 사용한다. 실제 사용자 DB·로그인·S3 전체 흐름을 검증하는 것은 아니다. 모의 응답 테스트와 실제 모델 품질 평가는 [평가 문서](recommendation-quality-evaluation.md)에서 구분한다.
