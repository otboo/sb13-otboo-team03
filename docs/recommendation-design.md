# 의상 속성 기반 추천 규칙

> 현재 코드에 구현된 규칙을 정리한 문서다. 온도 구간과 점수는 초기 정책이며 추후 조정할 수 있다.

## 1. 적용 범위와 구현 상태

날씨와 온도 민감도로 보정 온도를 계산하고, 의상의 두께 수준에 따라 적합한 의상 조합을 선택한다. LLM은 사용하지 않는다.

속성은 관리자가 자유롭게 등록할 수 있으며, 추천을 위해 특정 속성을 미리 생성할 필요는 없다. 단, 규칙 사전에 등록된 속성명과 선택값만 두께 정보로 해석한다.

| 구분 | 현재 상태 |
| --- | --- |
| 속성명·선택값의 두께 의미 해석 | 구현됨 |
| 한 의상의 두께 정보 종합 | 구현됨 |
| 보정 온도에 따른 두께 적합도 계산 | 구현됨 |
| 의상 ID별 두께 정보를 입력받아 코디 선택 | 구현됨 |
| 추천 서비스의 속성 조회·분석 및 알고리즘 전달 | 미구현, RED 테스트 작성 단계 |
| 속성 등록·수정 시 분석 결과 저장 및 재분석 | 미구현 |

현재 추천 서비스는 날씨와 프로필, 사용자 소유 의상을 조회하지만, 두께 정보를 전달하지 않는 기존 추천 메서드를 호출한다. 따라서 실제 추천 API에는 아직 속성 기반 선택이 적용되지 않는다.

## 2. 속성 해석

`AttributeSemanticAnalyzer`는 속성명과 선택값을 함께 확인하여 `ThicknessLevel`을 반환한다.

| 속성명 | 선택값 | 반환값 |
| --- | --- | --- |
| 두께, 두께감 | 얇음 | LIGHT |
| 두께, 두께감 | 보통 | MEDIUM |
| 두께, 두께감 | 두꺼움, 도톰함 | HEAVY |
| 그 외 속성명 또는 선택값 | 모든 값 | UNKNOWN |

적용 규칙은 다음과 같다.

- 속성명과 선택값의 앞뒤 공백을 `strip()`으로 제거한다. 중간 공백은 제거하지 않는다.
- 사전과 정확히 일치하는 표현만 사용한다. 부분 문자열로 의미를 추측하지 않는다.
- 속성명이나 선택값이 `null`이면 `UNKNOWN`을 반환한다. 빈 문자열도 사전에 없으므로 `UNKNOWN`이다.
- 동의어를 추가하려면 규칙 사전을 수정한다. 새로운 표현마다 enum을 추가하지 않는다.

예를 들어 `두께감=도톰함`은 `HEAVY`지만, `가격대=두꺼움`이나 `두께=두꺼움 아님`은 `UNKNOWN`이다.

## 3. 의상별 두께 정보 종합

`ClothesThermalEstimator`는 한 의상에서 해석한 두께 수준 목록을 입력받는다. 문자열 해석이나 DB 조회는 수행하지 않는다.

| 입력 예시 | 반환값 | 적용 규칙 |
| --- | --- | --- |
| LIGHT | LIGHT | 유효한 수준 사용 |
| HEAVY, HEAVY | HEAVY | 동일 수준은 중복 반영하지 않음 |
| UNKNOWN, LIGHT | LIGHT | UNKNOWN은 종합 과정에서 제외 |
| LIGHT, HEAVY | UNKNOWN | 서로 다른 유효 수준이 있으면 충돌 처리 |
| HEAVY, HEAVY, LIGHT | UNKNOWN | 개수가 많아도 충돌을 무시하지 않음 |
| UNKNOWN만 있거나 빈 목록 | UNKNOWN | 판단할 정보 없음 |

`UNKNOWN`은 두께를 모른다는 뜻이며 `MEDIUM`과 구분한다. 현재 보온성 판단에는 두께 수준을 사용하며, 실제 단열 성능을 측정하거나 소재·계절을 평가하지 않는다.

## 4. 보정 온도 계산

`BasicOutfitAlgorithm`은 다음 식으로 온도 민감도를 반영한다.

```text
보정 온도 = 실제 기온 + (온도 민감도 - 3) × 2.0
```

| 실제 기온 | 민감도 | 보정 온도 |
| --- | --- | --- |
| 17℃ | 1 | 13℃ |
| 17℃ | 3 | 17℃ |
| 17℃ | 5 | 21℃ |

현재 식에서는 민감도 값이 클수록 보정 온도가 높아진다. 추천 서비스는 민감도가 없으면 기본값 `3`을 사용한다.

속성 기반 추천에서는 보정 온도를 한 번 계산하여 두께 적합도와 아우터 추가 여부에 공통으로 사용한다. `ThicknessSuitabilityScorer`는 전달받은 보정 온도를 그대로 사용하고 민감도를 다시 반영하지 않는다.

## 5. 두께 적합도 점수

`ThicknessSuitabilityScorer`는 보정 온도 구간에서 선호하는 두께에 `1점`, 나머지 수준에 `0점`을 부여한다.

| 보정 온도 | LIGHT | MEDIUM | HEAVY | UNKNOWN |
| --- | --- | --- | --- | --- |
| 15℃ 미만 | 0 | 0 | 1 | 0 |
| 15℃ 이상, 25℃ 미만 | 0 | 1 | 0 | 0 |
| 25℃ 이상 | 1 | 0 | 0 | 0 |

현재는 선호하는 두께와 나머지만 구분한다. 예를 들어 더운 날에 `MEDIUM`과 `HEAVY`의 적합도 차이는 두지 않는다. `UNKNOWN`도 0점이지만, 두께가 보통이거나 부적합하다고 판정한 것은 아니다.

## 6. 의상 조합 선택

속성 기반 추천 메서드는 의상 목록, 의상 ID별 두께 수준, 실제 기온, 온도 민감도를 입력받는다.

```text
보정 온도 계산
→ 두께 적합도 내림차순으로 의상 목록 정렬
→ 종류별 첫 번째 후보 선택
→ 기본 조합 구성
→ 필요한 경우 아우터 추가
```

### 6.1 후보 및 동점 처리

- 의상 ID에 대응하는 두께 정보가 없거나 의상 ID가 없으면 `UNKNOWN`으로 평가한다.
- 점수가 같으면 입력 목록의 순서를 유지한다. 의상 ID로 동점을 정렬하지 않는다.
- 두께를 모르는 의상도 후보에서 제외하지 않는다.
- 모든 후보가 0점이어도 조합을 구성할 수 있으면 추천한다. 최소 적합도 제한은 없다.
- 다른 종류의 의상도 하나의 목록에서 정렬하지만, 최종 선택은 각 종류의 첫 번째 후보를 사용한다.

예를 들어 더운 날에 두 반팔이 모두 1점이면, 입력 목록에서 먼저 나온 반팔을 선택한다. DB 조회 순서에 따라 입력 순서가 달라질 경우 동점 선택 결과도 달라질 수 있다.

### 6.2 기본 조합 및 아우터

| 조건 | 반환 조합 |
| --- | --- |
| 상의와 하의가 모두 있음 | 상의 1개 + 하의 1개 |
| 상의·하의 조합이 불가능하고 원피스가 있음 | 원피스 1개 |
| 기본 조합을 구성할 수 없음 | 빈 목록 |
| 기본 조합이 있고 보정 온도가 15℃ 미만이며 아우터가 있음 | 기본 조합 + 아우터 1개 |

상의·하의와 원피스가 모두 있어도 상의·하의 조합을 우선한다. 기본 조합 없이 아우터만 반환하지 않으며, 아우터가 없으면 기본 조합만 반환한다. 보정 온도가 정확히 15℃이면 아우터를 추가하지 않는다.

신발·가방·액세서리 등은 현재 조합에 포함하지 않는다.

### 6.3 기존 추천 메서드

- 두께 정보 없이 기온·민감도만 받는 메서드는 입력 순서대로 기본 조합을 선택하고 아우터 추가 여부를 판단한다.
- 의상 목록만 받는 메서드는 입력 순서대로 기본 조합만 선택한다. 날씨 판단과 아우터 추가는 수행하지 않는다.
- 알고리즘 자체는 소유권을 검사하지 않는다. 추천 서비스가 사용자 ID로 조회한 소유 의상을 후보로 전달한다.

## 7. 후속 작업

- 추천 서비스에서 의상 속성을 일괄 조회하고, 해석·종합 결과를 알고리즘에 전달한다.
- 속성 등록·수정 시 분석 결과를 저장할지, 추천 시마다 해석할지 최종 처리 방식을 확정한다.
- 분석 결과를 저장한다면 원본 변경·규칙 변경 시 재분석과 실패 처리 정책을 구현한다.
- UNKNOWN과 비선호 두께의 우선순위, 최소 적합도 제한 등은 필요에 따라 개선한다.
- 소재·소매 길이·계절은 지원 규칙과 중복 반영 기준을 정한 후 확장한다.
